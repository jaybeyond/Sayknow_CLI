# Fork provenance — upstream independence

Sayknow-CLI began as a rebranded fork of an upstream MIT agent harness (see
[`NOTICE.md`](../NOTICE.md)). Through `sayknow-v0.5.x` the tree was a
reproducible function of `{upstream tag, fork layer}`, regenerated by a
four-layer pipeline (codemod + fork-identity + overlay + patches) on every
upstream release. The last full sync base was **upstream v0.12.0**
(released as `sayknow-v0.5.0`).

## Independence decision (2026-08-18)

Product direction diverged from upstream, so wholesale release-tracking was
retired. **This tree is now the single source of truth.**

- The regeneration pipeline was removed: `scripts/apply-rebrand.ts`,
  `scripts/apply-fork-identity.ts`, `scripts/extract-fork-layer.ts`,
  `scripts/fork-version-neutral.ts`, `scripts/gen-tree.ts`,
  `scripts/sync-upstream.sh`, and the whole `rebrand/` layer
  (identity/manifest/overlay/patches). If ever needed again, recover it from
  git history (last present at `sayknow-v0.5.2`, commit `934be022f`).
- The old "minimize patches, prefer overlay" constraint is void. Any file may
  be edited, refactored, or deleted like normal owned code.

## Working with upstream after independence

- The `upstream` git remote stays as a **reference**, not a dependency.
  Specific fixes may be ported opportunistically via `git cherry-pick` (or a
  manual port when the trees have drifted); they are reviewed like any other
  change and must pass the normal gates.
- Attribution stays: `NOTICE.md`, `README.md`, and MIT license history are
  legal record, not sync machinery. Do not strip them.
- Brand/identity gates stay (`rebrand-inventory.ts --strict`,
  `check-visible-definitions.ts`, `verify-g002-gates.ts`): they enforce SKC
  product identity in the shipped surface, independent of upstream syncing.

## Release policy (unchanged)

Releases run from the local `sayknow-fork` branch (published as
`origin/main`) via `bun run release <X.Y.Z>`, which tags `sayknow-vX.Y.Z`.
Plain `vX.Y.Z` tags are frozen upstream-derived history. See
`scripts/release.ts` and the release sections of `AGENTS.md`.
